# Playwright BDD Automation Framework

This project is a robust, industry-standard UI automation framework built with **Playwright**, **TypeScript**, and **Cucumber BDD** (via `playwright-bdd`). It utilizes the **Page Object Model (POM)** design pattern and Playwright **Fixtures** for dependency injection.

## 🏗️ Framework Structure

```text
PlaywrightTS/
├── .env                              # Environment variables (e.g., logins)
├── package.json                      # Project dependencies and NPM scripts
├── playwright.config.ts              # Global Playwright & BDD configuration
│
├── tests/UI_Test/                    # 🎯 Main Test Directory
│   ├── feature/                      # 1️⃣ BDD Scenarios (Gherkin .feature files)
│   ├── steps/                        # 2️⃣ Step Definitions & Fixtures (Playwright code)
│   ├── page/                         # 3️⃣ Page Objects (Locators and UI Actions)
│   └── types/                        # 4️⃣ Shared Types (Shared 'World' data)
│
└── Test Outputs/                     # 📊 Generated after running tests
    ├── .features-gen/                # Compiled tests generated by playwright-bdd
    ├── allure-results/               # Raw data for Allure Reporting
    ├── allure-report/                # Generated HTML Allure report
    └── playwright-report/            # Default HTML Report & Playwright Traces
```

## 🧠 Architecture Explanation

1. **Feature Files (`feature/`)**: 
   Written in plain English using Gherkin syntax (`Given`, `When`, `Then`). These files serve as living documentation and define the test scenarios.

2. **Step Definitions (`steps/*.steps.ts`)**: 
   These files connect the plain English Gherkin steps to actual TypeScript code. They remain entirely declarative and simply call methods on the Page Objects.

3. **Fixtures (`steps/fixtures.ts`)**: 
   Playwright fixtures are used to set up and tear down the environment for each test. Instead of using `new PageObject()` inside every step, fixtures automatically instantiate the Page Objects and inject them into the steps that need them.

4. **Page Object Model (`page/`)**: 
   Each page (or major component) of the application has its own class. This class is responsible for:
   - Storing all DOM locators (e.g., `this.page.locator('#id')`).
   - Performing actions (e.g., `clickLogin()`, `fillSearch()`).
   - Performing verifications/assertions (e.g., `verifyRedirected()`).

5. **World / Shared Context (`types/world.ts`)**: 
   Used to pass data seamlessly between different BDD steps within the same scenario (e.g., saving a generated `productName` in step 1, and verifying it in step 3).

## 🚀 Getting Started

### Installation
Make sure you have Node.js installed, then run:
```bash
npm install
npx playwright install --with-deps
```

### Environment Variables
Create a `.env` file at the root of the project with the necessary credentials:
```text
AMAZON_EMAIL=your_email@example.com
AMAZON_PASSWORD=your_password
```

## 🛠️ Running Tests

**Run all tests (headless):**
```bash
npm run test
```

**Generate and View Allure Report:**
```bash
npx allure generate ./allure-results --clean
npx allure open ./allure-report
```
